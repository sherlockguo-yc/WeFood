## 2. 实现方向与影响分析

### 2.1 方案比较

- 方案 A：服务端模板＋轻量表单。文件少、首屏简单，但多步骤记录、草稿、图片处理和设备冲突需要较多零散脚本。
- 方案 B：React＋独立业务 API。初始工程文件更多，但手机交互、共享类型、提交状态和后续分享页面边界更明确。
- 采用 B，延续已确认的 React＋Vite 设计；不再讨论语言或框架选型。

视觉采用“私人食记”：暖白背景、深色正文、低强度暖色强调、单列照片与文字卡片，手机底部四个入口。与密集管理表格相比更适合现场点菜与快速记录；不使用大面积渐变、辉光、动画或虚构食物封面。使用系统中文字体和 Lucide SVG 图标，颜色及间距由 CSS 变量统一定义。

### 2.2 三个实现维度

- 数据流：人物/店铺/菜品档案 → 手动选择一次就餐 → 点评与照片 → 服务端幂等保存 → 账号内查找。用户输入不能触发外部网页抓取。
- 状态：初始化、登录、空库、加载、编辑草稿、保存中、失败重试、版本冲突；成功状态必须以 API 返回为准。进入后台的手机不代表其他设备已保存。
- 安全及影响面：所有 ID 查询、更新、图片访问和关联校验都检查 `owner_id`；SQLite 和照片使用同一私有目录但分开存储。没有公共函数或共享样式影响其他仓库。

### 2.3 本批风险

| 风险 | 等级 | 处理 |
| --- | --- | --- |
| 账号越权或照片泄露 | 高 | 双账号对照测试，包括关联外部账号 ID 和图片 URL |
| 首次初始化被其他访问者抢先注册 | 高 | 本机一次性启动令牌；只显示给本机操作者，不出现在健康接口、URL 或普通日志中 |
| 重试重复创建、跨设备覆盖 | 中 | 请求幂等键、记录版本和数据库事务 |
| 照片超限/伪装格式/清理冲突 | 中 | 上传数与体积限制、解码检查、去 EXIF；未关联照片保留期清理不能删掉已关联内容 |
| SQLite 原生模块 ABI 不匹配 | 中 | 只在本项目 Node 24 安装，禁止重建其他项目依赖 |
| 新版本依赖 API 差异 | 中 | 按实际类型和对应版本文档实现，先用最小构建/测试验证，不猜测旧版 API |

## 5. 数据库与接口契约

### 5.1 表和归属

迁移建立 `users`、`sessions`、`invites`、`people`、`restaurants`、`dishes`、`meals`、`meal_people`、`meal_dishes`、`opinions`、`tags`、`tag_links`、`attachments`、`attachment_links`、`idempotency_keys`，以及迁移版本记录。

- 主键使用服务端生成的 UUID；业务表带 `owner_id`，关系写入校验父对象属于同一账号。
- `users` 保存用户名、密码哈希、账号状态及角色；初始化事务保证只能建立一个初始管理员。
- `sessions` 只存 token 摘要、所属账号、创建/失效/撤销时间、设备标签、最近活动及 CSRF 验证资料，不返回原 token。
- `people` 首次初始化仅创建“我”，其余人物由用户维护，不强迫提供朋友个人信息。
- 店铺、菜品、人物、标签、经历均保存版本及更新时间。店铺/菜品有历史引用时不级联删除就餐体验，采用归档并保留历史显示。
- `Meal` 至少包含店铺、方式、时间；金额可以为空。归档档案仍能显示历史，但不能被当作新记录的默认候选。
- `Opinion` 区分档案评价和当次评价，人物、店铺、菜品及经历关联都要验证归属；未填写的感受或再吃意愿是 `null`。
- 自定义标签与系统分类均在账号内，关联可区分店铺、菜品及当次经历；删除/合并标签不删点评。
- `Attachment` 不保存用户提交的任意文件路径，图片目录仅使用服务端 UUID。
- 幂等记录保存账号、键、请求摘要及已创建资源，键相同但正文不同返回冲突，不复用错误结果。
- 开启外键、WAL、合理 busy timeout；写入经历及关联使用单事务，任何越权 ID 导致全量回滚。

### 5.2 统一请求与响应

成功为 `data` 对象；失败为 `error` 对象，含稳定 `code`、简体中文 `message`、可选字段错误；不返回 SQL、堆栈或账号秘密。

- 未登录 `401`；未知或别人的私有资源 `404`，避免泄露对象存在性。
- 输入错误 `400`；版本/幂等冲突 `409`；上传超限 `413`；限频 `429`。
- 创建返回 `201`；删除/撤销明确返回成功状态，前端不依赖隐式空 JSON。
- 所有写请求校验可信 Origin 和 CSRF。首次初始化/登录使用非认证握手防护；认证后使用会话绑定 token，不能只通过 SameSite 声称完成 CSRF 防护。
- 输入由 Zod schema 校验，裁剪字符串空白、拒绝超长/非法日期/负金额；共享类型不能使服务端放弃运行时验证。

### 5.3 本批接口

- 初始化及认证：状态、一次性初始化、登录、本人信息、退出当前设备、改密码、设备列表/撤销、管理员邀请与邀请注册。
- 口味人物：列表、创建、修改、归档。
- 店铺：搜索/分页列表、详情、创建、带版本修改、归档。
- 菜品：店铺下列表、创建、带版本修改、归档；保存规格和备注。
- 标签：常用分类和自定义列表、维护、合并；按所选对象关联。
- 就餐：分页列表、详情、事务创建、带版本修改、删除；支持人物、菜品、分人感受、可选金额和照片关联。
- 点评：档案或当次体验的分人维护接口，禁止只有“店铺平均分”。
- 照片：上传、账号内读取、未关联删除/清理；本批没有公共图片 URL。
- 健康：返回最小运行状态，不返回路径、用户数或初始化令牌。
