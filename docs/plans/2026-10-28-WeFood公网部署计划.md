## 方案与安全边界

采用现有 GitHub CI → Release/R2 → webhook → N150 deploy-agent，不手动分发代码、不手动启停生产服务。Cloudflare 路由在 Dashboard API 更新，不写本地 ingress。

WeFood 独立使用 Node 24，安装到 `~/.local/wefood-node-v24.19.0`，不修改 N150 Node 20 或 PATH 全局配置；依赖安装到 `~/wefood-deps`。选用已核实未占用的 4318 端口，仅监听 loopback，入口由 Tunnel 提供 HTTPS。

地址不自动提供地图 Key。服务器复制已授权的 WeTravel 地图变量到 WeFood 受保护 `.env`，不打印密钥，不改 WeTravel；线上验证底图、POI 和域名授权，受限时报告不伪装通过。

## 执行步骤

1. 创建 `sherlockguo-yc/WeFood` 公开源码仓库，只发布可再现代码及构建依赖清单。
2. 写 CI、生产 restart 源脚本，测试/构建后打包 dist、package.json/lock、restart.sh、.version，不包含 node_modules/data/.env。
3. 验证 R2 可用上传凭据范围，不默认备份桶 token 能访问部署桶；GitHub Secrets 只能写不能读，不尝试提取已有 secrets。
4. 本机 SQLite 在线一致性备份，再复制其引用的照片到迁移包；经 SSH 到受保护目录，校验散列，不删除本机原数据。迁移不发布到 GitHub/R2。
5. 服务器配置独立 Node 24、WeFood .env 和数据目录，注册 deploy-agent 项目；项目还未部署时不人工运行 restart.sh。
6. Cloudflare API 获取完整 config，追加单条域名 ingress 并保留其余配置；DNS CNAME 指向已存在 tunnel，冲突则停止而非覆盖别人。
7. 提交/push，等待 CI/webhook/cron 完成部署；检查健康、版本、HTTPS、Cookie 和地图权限。
8. 完成记录发布状态、测试/迁移数量与未完成项；不输出私有账号、订单、图片内容或任何凭据。
