# WeFood 堂食地址与真实地图实现计划

- 状态：代码与自动化验证完成（2026-10-28）；真实供应商调用待可用 Key 验证
- 目标：堂食保存需店铺地址；复用 WeTravel 的腾讯地图接入模式，支持真实 POI 搜索选店、手动标点、私人店铺地图与筛选联动。
- 授权范围：用户要求真实地图并继续实现，使用腾讯底图与公开地点服务；不访问消费平台账号，不复制 WeTravel 的密钥，不改变 WeTravel。

## 方案与边界

采用 WeFood 独立腾讯适配层和 React 地图组件，不直接调用受旅行计划权限保护的 WeTravel API。沿用其固定上游、签名、超时、大小限制、有限并发、按北京时间持久化配额及脱敏错误方式。共享包方案留给两项目未来共同重构，本次不跨仓库变更。

第三方可接收搜索关键词、城市/区域、地图视野以及用户主动授权的定位。私人点评、人物、照片不传给腾讯。定位通过官方坐标转换从 WGS84 转为 GCJ-02；不长期保存用户位置。店铺位置只保存店铺坐标，拒绝伪造 POI 或推断营业状态。

地址与位置分开：堂食需非空地址，地图标记需 GCJ-02 位置。已有历史记录不批量补造或删除；旧店需补地址后新增堂食，外卖仍可无地址。旧经历编辑非地址字段不因旧数据缺地址被阻断。旧草稿恢复为无位置，取消选点保留其他输入。

## 文件及任务

1. `shared/geo.ts`：位置 schema、经纬范围、坐标类型、纯函数标记聚合；`shared/contracts.ts`、`web/src/api.ts` 扩展可空位置。
2. `server/library.ts`：新建/切换为堂食时检查店铺地址；版本冲突、幂等和历史兼容不变。
3. `server/maps.ts`：配置读取、腾讯关键词区域搜索、POI/详情、逆地理编码、GPS转换；鉴权后同源 POST 查询防止跨站耗额度，固定上游、防泄漏、按日及账号限额。
4. `server/config.ts`、`server/app.ts`、`server/index.ts`、`.env.example`：独立地图变量、初始化装配。无 Key 时不调用上游，界面显示配置缺失，不假装地图可用。
5. `web/src/components/FoodMap.tsx`：腾讯 SDK 单次加载、生命周期清理、批量店铺标记、客户端分组聚合、选点、定位、失败重试。
6. `web/src/components/PlacePicker.tsx`：区域＋关键词明确提交查询、候选 POI（真实名称/地址/类别）、地图选点、逆编码失败手填、保存前确认；不会输入一字请求一次。
7. `web/src/pages/Record.tsx`、`Restaurant.tsx`、`Discover.tsx`、`web/src/styles.css`：三入口共用位置选择，堂食地址必填与已有店补地址，“吃什么”列表/地图切换、标记点开卡片、待标记店数量与补标入口；同名分店可以新建。
8. `tests/maps.test.ts`、现有 API 测试、`e2e/core.spec.ts`：无地址堂食失败/外卖成功、旧数据编辑、坐标无效、账号隔离、Key不泄露、超时/限额/响应校验、选点与表单回填及未配置地图降级。正常流程仍测试全部。
9. 同步 `README.md`、现有需求追加章节和功能规格。构建、类型检查、全部测试、截图检查、提交；当前无 remote 则不伪造 push。

## 数据流与状态

搜索或点地图 → 显示候选地址和位置 → 用户采用 → 草稿 → 本人店铺创建/带版本更新 → 堂食保存 → 地图仅展示筛选命中且有位置的私人店铺。

状态：未配置/加载/地图可用/请求处理中/候选确认/定位拒绝/错误重试。地图错误不丢草稿；有文字地址可保存堂食，无坐标不显示虚假地图位置。更新私人位置不改变既有分享快照，位置本轮不加入公开分享白名单。

## 验收

- 新建堂食无地址在前端和 API 被拒绝，填写或选 POI 地址后可保存；外卖仍可无地址。
- 选 POI 回填名称、地址、GCJ-02 坐标及腾讯地点 ID；同名不同分店不自动混为一店。
- 已有店可以从记录页补地址/位置，走版本校验；旧记录不被清除、不补造。
- 地图和列表共用筛选结果，私人标记可打开店铺，密集标记显示分组数量。
- 未配置 Key、地图加载失败、拒绝定位/逆地址解析失败都有明确反馈，手填仍可使用。
- 只发送明确地理查询，不发送私人记录和密钥；Key缺失不能宣称真实地图验证通过。

## 真实集成验证限制

不读取 WeTravel `.env` 或真实 Key；用户未提供本项目 Key。用伪造响应和 SDK 适配测试验证契约，不将此描述为真实腾讯调用成功。接入完成后需配置 JS Key（域名限制）、WebService Key（接口权限及额度）和可选 SK，再做真实供应商验证。实际配额和收费以账号控制台为准，不自动申请付费。

## 验证结果

- 19 项 API/地图适配测试通过；类型检查通过。
- Chrome 手机流程 4 项通过，截图脚本默认跳过；含无 Key 降级、取消保留、POI 回填、标记联动、手动落点及迟到响应不覆盖手填。
- 生产构建由 E2E 启动步骤验证成功；生成并检查手机截图，未发现横向溢出或输入遮挡。
- 发现并修复两种竞态：取消/手填/换候选使旧解析失效；记录保存期间锁定输入，不让响应覆盖新草稿。
- 官方 SDK 动态文档确认使用 `zoom` 事件而非旧版 `zoom_changed`，并核对 MarkerStyle、MultiMarker、fitBounds、destroy、LatLng 和事件坐标。
- 真实腾讯集成、真机仍未验证；不复制 WeTravel 密钥，不修改其他项目。
