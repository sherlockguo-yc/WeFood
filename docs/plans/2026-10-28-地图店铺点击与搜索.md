# 地图店铺点击与名称搜索

- 状态：实现和自动化测试完成，待自动发布验收，2026-10-28。
- 用户确认：底图店铺可选中，支持搜索店铺名；完成后自动发布到已授权公网服务。

## 方案

延续腾讯底图与已有地图 Key。首页地图增加店名搜索、城市/区域输入和候选卡片，即使记忆库为空也能使用。选址页保留已有搜索并增加底图 POI 点击。共享搜索与选择状态，避免两套入口行为分叉。

官方事件文档 `https://lbs.qq.com/webApi/javascriptGL/glDoc/glMapEvent` 明确 `MapEvent.poi` 有 `name`、`latLng`，未承诺地点 ID。不能将点击坐标或未核实字段冒充 POI ID。点击店铺名称后用其名称和真实坐标进行附近查询（GCJ-02，最多1000米），唯一同名近邻可显示规范化卡片；歧义时展示候选供选择，不静默选择分店。空白点击保持手动标点。

备选是只搜名称不处理底图事件（不足以满足直接点击），或依赖 undocumented ID（不可接受）；采用点击名字＋坐标解析真实 POI 的可核实路径。

## 数据流、状态和边界

地图 POI点击/明确提交店名 → 查询候选 → 卡片 → 查看已有食记 / 加入记忆库 / 用这家店记录。仅用户主动操作触发查询，不自动扩大范围，不发送私人点评和照片。

查询中、无结果、多个候选、上游失败、限额、用户取消必须明确；旧请求不能覆盖新的点选。候选标记与私人标记使用不同视觉样式，私人过滤仍保持，不让公开候选冒充自己的推荐。

同一账号按腾讯 providerId 复用已有店，创建事务补去重，避免多设备重复加入；同名不同ID不合并。复用归档店时仍保留归档状态，让用户主动恢复。地图选“记录”先保存/复用店铺，再传内部restaurantId；记录页有不同店草稿时保留草稿并让用户明确换店，不丢评价和输入。

## 文件与步骤

1. `shared/geo.ts` 与 `server/maps.ts`：共享Place类型，搜索支持区域/GCJ中心二选一，规范化参数、结果；不暴露服务器密钥。
2. `web/src/components/FoodMap.tsx`：读取poi.name/poi.latLng并触发onPoi；没有POI时才触发手动onPick。候选和私人标记区分。
3. `web/src/components/usePlaces.tsx`：共享明确搜索、附近解析、分页和请求失效机制；`PlacePicker.tsx`复用。
4. `web/src/components/MapExplorer.tsx`、`Discover.tsx`：地图店名搜索/候选卡片/用户操作；空库或无筛选结果仍可浏览公开地图，不能编造推荐。
5. `server/library.ts`：同账号腾讯POI创建去重；`Record.tsx`：内部ID选店草稿兼容。
6. `tests/maps.test.ts`、`e2e/maps.spec.ts`：底图点击与空白分流、搜索名/附近、取消/失败/竞态、已收录复用与账号隔离、空库、草稿保护。
7. 类型检查、全部API/E2E、截图与控制台检查、真实腾讯附近查询契约验证，文档同步、提交push后等CI与deploy-agent上线。不手动重启N150，不改其他项目。

## 验收

- 点可识别店名显示地点卡片并能记录；无POI不伪造店名或ID。
- 首页地图可以按名称搜索，区域/附近条件明确，候选可选，记忆库空时也可用。
- 已有同POI复用食记，加入/记录不会重复创建；不同账号不共享私人档案。
- 多次快速点选以最后一次为准，出错可重试/搜索，保存与旧草稿不被静默覆盖。
- 页面和服务端测试通过，线上健康与版本核对；真实事件未在真机测试时不虚报全部实测。
