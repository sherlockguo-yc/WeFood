# WeFood 记忆库功能规格

> 现状文档：描述当前实现如何工作。修改功能前先读本文，实现变化时同步更新。决策原因见 `docs/requirements/WeFood产品与技术设计.md`。

- 更新日期：2026-10-28
- 运行：Node.js 24、Express 5、better-sqlite3、React 19、Vite 8。

## 1. 页面

底部四个入口，单列手机布局（最大宽度 560px），固定底栏适配安全区。

| 路径 | 页面 | 功能 |
| --- | --- | --- |
| `/` | 吃什么 | 按方式、同行人物、口味/场景标签、人均预算筛选；结果附推荐理由、必点、注意、上次时间 |
| `/library` | 记忆库 | 店铺 / 菜品 / 记录三个分类，搜索与标签筛选，新建店铺 |
| `/restaurants/:id` | 店铺详情 | 值得点、需要避开、分人感受、菜品管理、就餐时间线、编辑/归档、补一条评价、再记一顿 |
| `/record` | 记一顿 | 选店或新建店、时间、堂食/外卖、同行人、实际吃的菜、分人分菜感受、花费、备注、照片 |
| `/me` | 我的 | 回顾统计、口味人物、标签管理/合并、设备会话、退出、改密码、邀请朋友、导出 |
| `/shares` | 分享管理 | 新建（预览后发布）、复制/打开、更新内容、续期、撤销 |
| `/s/:token` | 公开分享 | 免登录查看快照；到期/撤销显示状态说明 |
| `/join?invite=` | 邀请注册 | 未登录时显示注册表单 |

## 2. 数据与规则

- 业务表：`people`、`restaurants`、`dishes`、`meals`、`opinions`、`tags` 以 JSON 存储字段，带 `owner_id`、`version`；另有 `users`、`sessions`、`invites`、`attachments`、`idempotency_keys`、`shares`、`map_usage`。
- 店铺 `location` 可空，包含 `lat`、`lng`、`crs: GCJ-02`、`source: manual/tencent`、可选 `providerId`（腾讯来源必需）。旧数据无此字段视为未定位。
- 新建堂食或从外卖切换为堂食需店铺非空地址，前后端均校验；旧无地址堂食在同店编辑仍可维护。外卖不强制地址，历史不批量更改。
- 所有读写按登录账号的 `owner_id` 过滤；别人的 ID 一律返回 404。关联写入校验人物、店铺、菜品、照片都属于本人。
- 就餐保存在一个事务内写入就餐与其中的评价；点评的人必须在同行人中，评价的菜必须是本次选中的菜。
- 店铺、菜品、人物删除为归档，历史保留；就餐删除会同时删除其中的评价。
- 编辑带 `version`，旧版本保存返回 409；前端保留输入并提示，再次保存以用户内容为准。
- 创建请求可带 `Idempotency-Key`：相同键相同内容返回同一条记录；相同键不同内容返回 409。
- 金额以“分”保存，可为空；统计只计有金额的记录并显示缺失数量。
- 草稿存于本机 `localStorage`（按账号区分），保存成功后清除，不跨设备同步。

## 3. 选店规则（`GET /api/discover`）

1. 先应用硬条件：方式（有该方式的就餐记录）、标签（店铺标签或某道菜的标签命中）、预算（需填写人均且不超过）。不满足直接排除，不自动放宽。
2. 评价人：选了同行人时只看他们，否则看所有有评价的人。
3. 打分：喜欢 +2、不合口味 −3、想再吃 +2、不再点 −3，菜品评价权重 0.5；3 天内刚吃过 −2，超过 30 天没去且有好评时加分。
4. 已评价的店排在未评价前；未评价的店标“尚未评价”。
5. 必点：有人正面评价且无人负面评价的菜；注意：列出谁不喜欢哪道菜。

## 4. 认证与安全

- 首个账号需初始化令牌（终端打印或 `WEFOOD_SETUP_TOKEN`），之后仅能通过管理员邀请注册（7 天有效、一次性）。
- 密码 bcrypt（cost 12），至少 10 位；登录/注册每 IP 15 分钟 30 次限制。
- 会话：随机 token，数据库只存 SHA-256 摘要；HttpOnly、SameSite=Strict Cookie，30 天有效。每台设备独立会话，退出只影响当前设备；可在“我的”移除其他设备；改密码会注销全部设备。
- 写请求校验 `Origin` 在 `TRUSTED_ORIGINS` 内，并校验 `X-CSRF-Token`（未登录用握手 Cookie，登录后用会话令牌）。
- 照片：最多 8 张、每张 10MB，经 sharp 解码验证、纠正方向、去除元数据、转 WebP；仅本人可读（`Cache-Control: private, no-store`）。被记录或有效分享引用的照片不能删除；未引用超过 7 天的照片在服务启动时清理。
- 店铺链接只接受 http/https，仅用于跳转，服务端不访问。

## 5. 分享

- 选择店铺后自动带上被评为喜欢/想再吃的菜及对应评价，以及店铺和这些菜的照片；不包含备注、金额、就餐记录、不喜欢的评价。可选择是否显示评价人名字。
- 发布前可预览（`POST /api/shares/preview`）。
- 有效期：3 天、7 天、1 个月、3 个月、永久或自定义天/月；月按北京时间日历月计算，月末溢出取目标月最后一天。永久存为空。
- 更新内容按当前记录重建快照，不改变有效期；续期从当前时间重新计算；撤销不可恢复。
- 公开接口每次访问实时检查状态，到期/撤销返回 410，正文和照片都不可访问；响应 `no-store`、`noindex`、`no-referrer`。

## 8. 店铺位置与地图

- `PlacePicker` 共用于记录页、记忆库新店和店铺编辑。手填地址修改会清除旧坐标，避免地址与地图标记不一致；地图选址确认后保存位置，取消不改草稿。
- 堂食地址必填；已有店在记录时复用地址并可修改，修改走版本检查，局部保存成功保留资源 ID/版本以便重试；保存期间锁定表单避免响应覆盖新输入。
- POI 搜索按用户明确提交的城市/区域与关键词查询，分页沿用已提交条件；手动落点使用逆地址解析，失败保留位置供手填。用户手填或改选候选后，迟到解析结果不再回填。
- “吃什么”提供列表/地图切换，两者使用同一份 `/api/discover` 结果；无坐标的店列在待标记列表。地图使用腾讯 GL SDK，`zoom` 事件刷新客户端像素网格聚合；单标记显示食记卡片，聚合点击放大。
- `GET /api/maps/config` 登录后返回 JS Key、查询可用状态，不返回 WebService Key/SK。`POST /api/maps/{search,detail,reverse,translate}` 受登录、Origin 和 CSRF 保护。
- 地图请求固定上游 `apis.map.qq.com`，可选 SK 签名，最多并发 2、超时 10 秒、响应上限 2MB、不自动重试；`map_usage` 持久化每日全局和账号预算，按北京时间日期刷新。
- 手机原始定位为 WGS84，通过腾讯 `type=1` 转成 GCJ-02 后居中，不持久保存个人定位。地点保存明确 GCJ-02；逆解析不使用行政区划中心代替点击点。
- 配置：`WEFOOD_TENCENT_JS_KEY`、`WEFOOD_TENCENT_KEY`、可选 `WEFOOD_TENCENT_SK`，以及 `WEFOOD_MAPS_DAILY_LIMIT`/`WEFOOD_MAPS_USER_DAILY_LIMIT`。无 Key 显示明确不可用说明，地址可手填。
- 沿用 WeTravel 方案但没有改变其代码、Key 或权限；位置没有加入公开分享字段，快照规则保持。地图仅由用户打开相关入口后加载，用户地理查询会发送给腾讯，私人点评/人物/照片不主动发送。
- 官方动态文档已核对 `MultiMarker.setStyles/setGeometries`、`MarkerStyle`、地图 `zoom`、`destroy/getZoom/fitBounds`、点击 `latLng`、`LatLng.getLat/getLng`；模拟测试不代表真实供应商调用通过。

## 9. 底图POI点击与地图店名搜索

- `FoodMap` 区分 `MapEvent.poi` 和空白点击。POI只读取官方 `name`/`latLng`，交给 `usePlaces`；空白才逆地址解析，不猜测底图地点ID。
- 点击店名使用 `POST /api/maps/search` 的 `keyword`＋`center:{lat,lng,crs:'GCJ-02'}`＋`radiusMeters:1000`；搜索也可用 `region`，区域与附近二选一。只有全部结果已返回且150米内唯一同名才自动显示候选卡片，否则展示分店候选。
- `usePlaces` 共用状态、分页和请求失效机制；搜索按钮/Enter明确提交，输入不触发逐字请求；新查询重置旧分页；手填/取消/换候选使迟到结果失效。
- 首页 `MapExplorer` 提供店铺名和城市/区域输入，也可选择地图中心附近；空库或没有符合私人筛选的店时仍可搜公共地点，不将公共地点当推荐。
- 候选标记蓝色，自己的食记橙色。候选卡片可以加入记忆库/用这家店记录；已收录提供查看已有食记。加入只建店，不自动生成就餐或评价。
- 同账号相同腾讯providerId创建事务内复用原档案，不覆盖旧点评；不同账号、不同地点ID不合并。PUT若占用另一店的腾讯ID返回409；归档店需主动恢复。
- 从地图进入记录页传内部restaurantId；遇到另一店旧草稿不覆盖，提供改用地图店/继续原草稿。明确换店清原菜品和评价，保留备注/照片；记录页选到另一已收录POI也复用对应内部ID，避免改写原店历史。
- 验证：21项后端测试通过，7项Chrome手机流程通过，截图脚本默认跳过。新增覆盖底图/空白分流、首页搜索、POI匹配、空库入口、重复收录与隔离、旧草稿、分页未完整不误确认及搜索失败不遗留旧页码；真机点击事件未验证。
- 线上验证：CI run `40686896826` 成功，N150部署版本 `a71e86f`；公网 JS 与该 Release 产物哈希一致。服务器真实腾讯附近名称搜索返回10条GCJ-02候选，不打印凭据、不修改私人数据。SSH入口曾短暂超时后恢复，网站健康持续正常。

## 10. 记录页菜品显示与菜单能力边界

- 记录页从本人库按内部店ID获取菜品，单页1000按offset继续加载至末页；结果带所属店ID，加载或失败期间不展示旧列表，防止换店串菜。
- 既有菜品显示数量及规格，用户勾选实际吃过的菜才产生可点评项目。失败显式提示和重试，不清除草稿、已选ID或点评；没有数据显示“尚未记录这家店的菜品”，不等同于这家店没有菜。
- 界面明确标示已录入菜品不是完整菜单。当前没有外部菜单自动获取，腾讯POI不提供菜单；不能将特色菜、套餐或公共评价当完整菜品清单。
- 数据来源调研及尚未授权的接入方案见需求文档第18章；没有取得具体分店公开菜单来源或获授权接口之前，不创建假菜单或恢复私人消费账号访问。
- 本轮类型检查、生产构建、21项后端测试、8项Chrome手机流程通过，截图脚本默认跳过；新增回归验证已有菜品/点评、加载失败重试、备注保留、换店旧菜隔离和无完整菜单空态。普通测试输出清理被安全保护拦截后保留旧产物，改用新隔离输出/数据库完成验证，未删除受保护旧目录。

## 11. 79号渔船公开菜品参考

- `GET /api/dish-references?name=...` 在登录鉴权后返回维护的品牌参考。无外部请求，不回传私人店名给第三方；按品牌名规范化匹配，其他餐馆或179号渔船等近似名不匹配。
- 数据在 `shared/dishReferences.ts`，包含品牌微信公众号2025-07-14文章实际图片核实的13道菜；scope=brand、coverage=partial、核查日期2026-10-28。不是实时菜单API，不保证当前分店供应，不使用旧价格当现价。原图只用于本地核对，不打包或公开转载图片。
- 记录页 `DishReferences` 显示来源/发布日期/核查日/品牌范围，并使用与已有菜品相同的内联评价行。可直接点评好吃/一般/不好吃并选中，只有保存才创建Dish及就餐；参考存在不代表吃过或喜欢。
- 草稿 `dishOrigins` 保存选中菜来源；来源由新增 `origin` schema 持久化（旧菜默认null）。已有同名无规格菜复用，不覆盖原菜备注或点评；移除新菜/更换店清对应来源和本次评价，保留备注照片。地图把新店改成其他品牌也确认清菜，不串参考。
- 已有菜加载/失败期间参考和手动新增菜禁用，避免查询未完成导致重复建菜；选中菜的分人评价和弱网重试继续使用现有机制。
- 菜品详情可查看原始来源；分享仍使用已有白名单，不自动增加origin字段，公开参考不自动进入必点/避雷。
- 验证：类型检查、生产构建、23项后端测试和11项Chrome手机流程通过；测试包含13项品牌名、部分覆盖、认证只读、来源保留、不导入未选菜、回访复用、取消评价/草稿恢复/换品牌隔离和加载手动防重复。
- 未完成：完整分店菜单、现场现售海鲜品种/做法、通用商户菜单API；携程深圳湾20项/岗厦24项特色菜和宴席套餐仍只作为调研资料，不自动跨店套用。

## 12. 菜品行内三档评价

- `Record` 将“吃了什么”区域改为“菜品评价”，已录入、新增、公开参考同用 `DishRatingRow`；每菜每人物有好吃/一般/不好吃按钮，不再只以Chip标记吃过。
- 三档按钮直接写原feelings值like/neutral/dislike，并在同一次状态更新中选中菜，参考新菜附来源。不触及接口、历史评价或分享数据模型。
- 未选也能直接评分，未评分保持null；再点当前档清评分但保留吃过、again/note。独立取消吃过清该菜所有人物本次评价，没吃的菜不自动选，未评不默认一般。
- 每菜独立人物口味，选中后可填想再吃/不再点和一句话。整体“感受”区域仅渲染整家店，不重复菜品控件。
- 来源参考与已有同名无规格菜复用原ID，每菜人物只渲染一组；旧草稿的新菜与已录菜同名时迁移评分键和选择到已有ID，保留备注，取消可真正清掉旧选择，不隐藏重复保存。
